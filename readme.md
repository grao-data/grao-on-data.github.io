## How I work

I work with prototypes and wireframes, because a visual example demonstrates a thought process faster than a written spec does. I ground design decisions in real data, so I query the schema while I wireframe instead of designing against a guess. When live testing shows a decision is wrong, I change the solution.

I use Claude Code to draft PRDs and build wireframes, but I check it's output as an subject matter expert must. I verify its claims against the actual code and data, serving as a prototypes first user/tester. I run structured interviews with users, so that I build what customers need and what the business can sell.

I write for the reader in front of me. Engineers get precise specs, customers get plain language, and executives get short summaries. If needed, in a single day I can move from a schema query to a requirements doc to a UI layout.
